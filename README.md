# SQUARE — Bird Net & Invisible Grill

Production website for SQUARE, built with Next.js 15 (App Router), React 19 and
TypeScript. No CSS framework — the design system lives in `app/globals.css`.

## Run

```bash
npm install
npm run dev
```

Open http://localhost:3000

## Structure

```
app/                      Routes, metadata, sitemap, robots, 404 and error pages
components/
  layout/                 Header (sticky, dropdown, mobile drawer) and Footer
  home/                   One file per homepage section
  services/               ServicePage template shared by every /services/<slug>
  contact/ faq/ videos/   Page-specific interactive pieces
  ui/                     Reveal, Accordion, BeforeAfter, ProjectGallery,
                          VideoPlayer, CountUp, PageHero, CtaBand, map, icons
data/                     All editable content (see below)
lib/leads.ts              Lead validation + FormSubmit delivery
lib/seo.ts                Site URL, per-page metadata, breadcrumb schema
scripts/build-media.mjs   Image pipeline (originals -> optimised WebP)
media-source/             Original client + generated assets, never shipped
```

## Editing content

Everything the client is likely to change is in `data/` — no copy is buried in
JSX:

| File | Contains |
| --- | --- |
| `data/site.ts` | Contact details, WhatsApp link builder, metrics, service areas, process, materials, why-choose, reviews |
| `data/services.ts` | The six services — each entry drives both the index and its own page |
| `data/projects.ts` | Project gallery and case-study content |
| `data/faqs.ts` | FAQ categories, plus the homepage selection |
| `data/videos.ts` | Client video clips and their poster frames |

Adding a service is a data entry in `data/services.ts` plus a one-line route
file under `app/services/<slug>/page.tsx`.

## Before launch — items marked `TODO(client)`

Search the repo for `TODO(client)` and confirm each one:

- **Metrics** (`data/site.ts`) — years, projects, customers, warranty period.
- **Reviews** (`data/site.ts`) — the rating, review count and testimonials are
  indicative copy and must be replaced with verified Google reviews.
- **Project details** (`data/projects.ts`) — imagery is real client work; the
  locations and narrative copy should be confirmed.
- **Social links** (`data/site.ts`) — empty, so the footer icons are hidden.
  Add the real profile URLs to show them.
- **Legal pages** — `app/privacy-policy` and `app/terms` need a legal review.
- **Domain** — the canonical origin is `https://squarebirdnet.com` (apex,
  Netlify's primary domain; `www` redirects to it). It is pinned in
  `netlify.toml` as `NEXT_PUBLIC_SITE_URL` and drives canonicals, Open Graph,
  `robots.txt` and `sitemap.xml` via `lib/seo.ts`. It must match Netlify's
  primary domain, or every URL in the sitemap becomes a redirect.

## Lead form

The form emails enquiries to `squarebirdnetservice@gmail.com` through
[FormSubmit](https://formsubmit.co) — no server or credentials needed.
`lib/leads.ts` holds the integration and validation.

1. **Activate once:** after deploying, submit the form one time. FormSubmit
   emails an "Activate Form" link to the inbox; nothing is delivered until it
   is clicked (check spam).
2. **Hide the address (recommended):** the activation screen shows a random
   alias for the inbox. Set it as `NEXT_PUBLIC_FORMSUBMIT_ID` and rebuild.

Spam protection: hidden honeypot field, 3-second minimum fill time, links
rejected in the message, and FormSubmit's keyword blacklist. Without
JavaScript the form still posts straight to FormSubmit (with its captcha).

## Deployment (Netlify)

Netlify builds from the GitHub repository with `npm run build` (see
`netlify.toml`) and runs Next.js on its OpenNext-based runtime. Security and
cache headers, plus legacy-URL redirects, live in `next.config.mjs`; the
www → apex redirect lives in `netlify.toml`.

## SEO

- `npm run audit:seo` (after `npm run build`) starts the production server,
  crawls every page and checks titles, descriptions, H1s, heading order,
  canonicals, robots tags, Open Graph, JSON-LD, internal links and anchors,
  images, the sitemap, `robots.txt` and the 404 response. It exits non-zero
  on any error.
- Search Console setup and indexing checklist: `docs/GOOGLE-SEARCH-CONSOLE.md`.

- Per-page title, description, canonical, Open Graph and Twitter tags come from
  `pageMetadata()` in `lib/seo.ts`. Share images are 1200x630 JPEGs in
  `public/images/social/`, generated by `node scripts/build-media.mjs social`.
- `sitemap.xml` takes each URL's `lastmod` from the last git commit touching
  that page's source files (`lib/lastModified.ts`).
- Structured data: WebSite + HomeAndConstructionBusiness (layout), Service +
  FAQPage (service pages), FAQPage (`/faq`), BreadcrumbList (all inner pages).
- `app/sitemap.ts` lists indexable pages only; privacy and terms are
  `noindex, follow`, carry no canonical, and stay crawlable in `app/robots.ts`.
- `app/not-found.tsx` (404), `app/error.tsx` and `app/global-error.tsx` handle
  missing pages and runtime errors.

## Media pipeline

Original photographs, the logo and video poster frames live in `media-source/`,
outside `public/` so the heavy originals are never deployed. To regenerate the
optimised WebP derivatives in `public/images`:

```bash
node scripts/build-media.mjs
```

Client videos in `public/videos` are re-encoded for the web (H.264 CRF 28,
30 fps, 96 kbps AAC, `faststart`) and are never autoplayed — posters are
extracted stills, and an MP4 is only fetched when a visitor presses play:

```bash
ffmpeg -i in.mp4 -c:v libx264 -preset slow -crf 28 -r 30 -pix_fmt yuv420p   -c:a aac -b:a 96k -ac 2 -movflags +faststart out.mp4
```
